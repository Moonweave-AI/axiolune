# 遗留迁移、双跑与切换

## 1. 迁移目标

迁移要同时完成四件事：

1. 把离散字段、页面和脚本映射为稳定的金融本体；
2. 保持订单、成交、持仓、资金、研究和报告的历史/点时语义；
3. 在新旧系统并行期间证明结果、权限和操作一致；
4. 可按业务最小单元切换、核对、回退并最终退役旧路径。

迁移不以“数据复制完成”或“新页面可打开”为成功标准。

## 2. 已发现的迁移特征

附件审计显示：

- 现状覆盖工作台、数据、量化研究、主动研究、OMS/IMS/UFT、算法、风险、产品和 AI；
- 前端至少存在黑色终端、深色 OMS/IMS、浅色企业应用和独立 AI 面板等多套体验；
- 订单 CSV 约 2,474 行 × 20 列，持仓 CSV 约 802 行 × 30 列；
- 存在 19 位订单标识，超过 JavaScript 安全整数，必须按字符串迁移；
- 时间戳含毫秒，交易日/事件时间/记录时间未完全区分；
- 多个 code/枚举缺少字典，零、空、未知和不适用语义不清；
- 部分单位写在列名，目标字段全部为空；
- 现有技术包含 Umi/React/DVA/Ant Design/DevExtreme/ECharts/Chart.js、Axios、WebSocket、DataHub/SQL API 与微前端迹象；
- 运维存在文件配置、静态秘密、Cron/终端进程和手工操作。

这些是迁移输入与风险证据，不应被固化为目标设计。

## 3. 迁移原则

- 先观测、后读取、再提案、最后写入；
- 新本体使用规范 ID，保留所有源系统 ID 的 `ExternalIdentifier`；
- 原始数据不可变保存，规范化和修订另建版本；
- 业务含义不明确时进入 `UnresolvedMapping`，不猜测；
- 迁移、回填、核对和修复均为可审计运行/Action；
- 新旧双写只在有唯一幂等键、写入围栏和逐笔核对时使用；
- 切换以账户、策略、市场、数据产品或用户组为最小波次；
- 回退不删除新系统历史；保留时间线并恢复权威路由；
- 只有消费者、数据、合规和恢复条件全部满足才退役旧系统。

## 4. 迁移清单

为每个遗留资产创建 `LegacyAsset`：

| 类别 | 必录信息 |
| --- | --- |
| 系统/页面 | Owner、用户、旅程、输入/输出、使用频率、替代模块 |
| 数据库/表/CSV | Schema、主键、时间、单位、质量、规模、保存、许可 |
| API/消息/共享内存 | 协议、序号、幂等、延迟、错误、身份和网络 |
| Cron/脚本/Notebook | 触发、依赖、Owner、输出、副作用、恢复 |
| 账户/权限 | 人/服务、范围、审批、秘密引用、到期 |
| 算法/规则 | 版本、参数、输入、边界、黄金结果和 Owner |
| 报告/文件/媒体 | 模板、快照、来源、审批、分发、保留 |
| 外部供应商 | 合同、SLA、数据许可、协议、测试和退出 |

每项标记 `retain / migrate / replace / retire / unresolved` 和目标日期。

## 5. 语义映射

### 5.1 映射模板

| 源字段 | 源含义 | 目标对象.属性 | 转换 | 时间/单位 | null/zero | 质量规则 | Owner |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `order_id` | 源委托标识 | `Order.externalIdentifiers` | 原样字符串 | 不适用 | 不可空 | 长度/唯一/来源 | OMS Owner |
| `ts_ms` | 待确认 | `OrderEvent.occurredAt` | epoch ms → zoned | Asia/Taipei? 待确认 | 不可空 | 范围/单调 | Source Owner |
| `qty` | 待确认总量/剩余量 | 对应类型化数量 | decimal | share/lot 待确认 | 零语义确认 | 状态机核对 | Domain Owner |

所有“待确认”必须形成访谈问题和阻断/非阻断分类。

### 5.2 标识解析

- 为 Instrument、Party、Product、Portfolio、Account、Order、Execution 建规范 ID；
- `ExternalIdentifier` 保存 `{source, id_type, value, valid_time}`；
- 合并/拆分实体是带审批和前后证据的 Action；
- 规范 ID 不复用被删除实体，不依赖可变证券代码；
- 19 位及更长数字标识在数据库、JSON、CSV、前端和 Excel 导出全链路按文本；
- 对同一标识冲突、前导零、编码/全半角、大小写建立规则和隔离。

### 5.3 时间与点时

- 源时间先保留原值、时区推断依据和解析状态；
- 区分交易日、业务日、事件发生、来源接收、平台记录和有效期；
- 不用文件修改时间代替业务时间；
- 历史修订以双时态追加，不覆盖“当时所知”；
- 财报、成分、分类、公司行动和借券数据按实际可知时间映射；
- DST/跨市场/夜盘虽当前可能少见，也由值类型显式支持。

### 5.4 数值、单位与缺失

- decimal/定点类型按业务精度定义，不经 IEEE 754 浮点中转；
- 单位从列名迁移为 ValueType 元数据；
- 金额携带币种，比例区分 0–1、百分数和 BP；
- `null/unknown/not_applicable/not_calculated/zero` 分开；
- 源系统 magic number 或枚举 code 保留原值并映射到受治理字典；
- 无法映射的记录进入隔离，不默认映射为 0 或“其他”。

## 6. 迁移技术模式

### 6.1 适配器/防腐层

遗留 API、Redis Pub/Sub、共享内存、文件和数据库由适配器转换为：

- 规范领域事件；
- Object/ExternalIdentifier；
- 健康、序号、来源和质量状态；
- 受控 Action 的外部端口。

适配器不得把遗留表结构泄露到公共契约，也不得偷偷重写业务语义。

### 6.2 数据获取

| 模式 | 适用 | 要求 |
| --- | --- | --- |
| 快照 + CDC | OLTP 主数据/状态 | 一致切点、日志位置、去重、Schema 变化 |
| 事件订阅 | 订单/成交/行情 | 来源序号、重连、缺口回补、原始报文 |
| 文件批量 | CSV/报告/外部交付 | 清单、校验和、幂等、隔离和归档 |
| API 拉取 | 供应商/小规模对象 | 游标、限流、修改时间和全量核对 |
| 历史导出 | 冷数据 | 不可变、分区、点时、控制总数 |

### 6.3 Strangler 路由

在统一入口后按能力逐步路由：

- 查询：新 Object API 优先，未迁移对象由 legacy adapter；
- 动作：Action Service 是唯一入口，按账户/策略选择旧/新执行器；
- 事件：新旧事实进入统一信封并标识来源；
- UI：统一应用壳链接遗留页面，逐模块替换；
- 身份：先统一 SSO/审计，再迁移细粒度授权。

## 7. 历史数据迁移

### 7.1 顺序

1. 固定数据契约和映射版本；
2. 复制不可变 Raw，并记录文件/表快照、行数、大小、哈希；
3. 规范化标识、时间、单位和枚举；
4. 运行质量检查，隔离异常；
5. 创建对象、链接、事件和分析投影；
6. 对控制总数、逐记录样本、业务恒等式和点时查询；
7. 由 Data/Domain Owner 签署批次；
8. 增量 CDC/事件追平；
9. 生成 `MigrationRun` 和差异清单。

### 7.2 核对层次

- 传输：文件数、字节、哈希、行数；
- Schema：字段、类型、精度、枚举；
- 实体：主键唯一、标识冲突、链接悬空；
- 财务：数量、金额、费用、资金、持仓控制总数；
- 状态：订单/成交状态机与最终态；
- 时间：每日/市场/账户分区和迟到；
- 业务：净值、风险、因子、报告黄金结果；
- 权限：对象/属性可见集合和导出范围。

金额/数量容差由值类型和业务批准，不使用一个全局浮点容差。

## 8. 双跑模式

### 8.1 双跑阶段

| 模式 | 旧系统 | 新系统 | 目的 |
| --- | --- | --- | --- |
| Observe | 权威 | 只采遥测 | 理解负载、失败和依赖 |
| Dual-read | 权威 | 读取/计算 | 数据与口径比对 |
| Shadow | 权威执行 | 同输入、不产生副作用 | 规则/算法/性能比对 |
| Proposal | 权威执行 | 生成动作建议 | 用户与审批验收 |
| Canary-write | 非目标账户权威 | 指定账户/策略权威 | 小范围真实验证 |
| New-primary | 只读/回退 | 权威 | 观察和退役准备 |

### 8.2 差异模型

`ComparisonResult` 包含：

- 业务键、源/新版本和输入快照；
- 旧值、新值、绝对/相对差和类型化容差；
- 分类：时间差、数据缺失、映射、精度、规则、软件错误、预期设计差异；
- 严重度、可否自动修复、Owner 和 SLA；
- 证据、修复版本和复验结果。

不可只汇报“匹配率 99%”；1% 可能包含全部高金额订单。按金额、账户、状态、风险和业务截止分层。

### 8.3 影子安全

- 影子订单使用物理隔离的仿真适配器或写入硬禁用；
- Replay 事件标记 `replay_id`，消费者不触发通知/外部动作；
- Shadow 结果不能回写生产风险/账户；
- 用生产输入时仍按生产权限和数据分类；
- 影子计算资源不能抢占 Tier 0。

## 9. 切换单元与准入

建议切换键：

- 数据产品/来源；
- 用户组/功能；
- 产品/组合；
- 账户；
- 策略/算法；
- 市场/柜台；
- 报告模板/渠道。

每个切换单元具备：

- 显式路由和写入围栏；
- 唯一幂等/业务键；
- 新旧实时比较；
- 独立 SLO、额度和暂停开关；
- 回退后的事件/数据合并方案；
- Owner、Checker、观察窗和成功/停止阈值。

## 10. 上线准备门

### 10.1 T-30 至 T-7

- 范围、窗口、参与者、联系和沟通确认；
- 数据迁移/CDC 连续稳定，差异低于批准阈值；
- 1×/2×/5× Replay、故障、恢复和安全验证通过；
- 外部券商/行情/网络/证书/白名单验证；
- 数据库/本体/API/Event 兼容和回退演练；
- 备份恢复和 DR 健康；
- 运行手册、仪表板、告警和值班演练；
- 用户培训、权限复核和业务 sign-off；
- 冻结冲突变更。

### 10.2 T-1

- 记录新旧版本、数据/事件水位和控制总数；
- 清零或接受所有阻断差异；
- 验证密钥、证书、时间同步、容量和降级；
- 确认回退脚本/Action 不依赖同一故障；
- 再次确认 Go/No-Go 和停止阈值。

## 11. 切换执行

1. 宣告开始，冻结非必要写入/变更；
2. 记录旧系统最后权威水位；
3. 等待/核对 CDC 与事件追平；
4. 启用目标单元写入围栏，防双主；
5. 将少量流量路由至新系统；
6. 验证认证、策略、订单/数据状态、外部回执和审计；
7. 按波次增加账户/策略/用户；
8. 每波观察技术 SLI、业务差异和风险；
9. 达到停止阈值立即暂停扩展或执行回退；
10. 完成后旧路径保持只读/热备至观察期结束。

## 12. 停止与回退条件

必须预先量化，例如：

- 任何重复订单、错误账户/市场或未授权动作；
- 订单/成交/资金/持仓不变量破坏；
- 外部未知状态数量或持续时间超过阈值；
- 硬风控错误、超时或 fail-open 非预期；
- Tier 0 SLO 快速燃烧或审计不可写；
- 新旧差异集中在高金额/受限对象；
- 无法在 RTO 内定位或恢复；
- 数据/权限/密钥安全事件。

回退流程：

1. 停止新流量并保持证据；
2. 对新系统未决动作分类，不盲目重发；
3. 查询外部权威状态；
4. 确定旧系统恢复水位和写入围栏；
5. 恢复旧路由；
6. 核对订单、成交、持仓、资金和审计；
7. 向业务/管理层沟通实际影响；
8. 修复并重新通过准入门。

数据库/本体不可逆变化优先前滚修复；所谓“代码回滚”不保证状态自动回滚。

## 13. 切换后观察

- Tier 0 每笔/每状态实时核对，Tier 1 按批准频率；
- 比较流量、错误、延迟、业务分布、人工操作和用户反馈；
- 观察至少覆盖市场开/收盘、日终、周/月截止和一个异常场景；
- 旧系统保持可读取证据，不允许继续隐式写入；
- 清理临时账号、白名单、Feature Flag、双写和高采样；
- 更新 Owner、运行手册、架构图、CMDB/服务目录；
- 只有观察门通过后才进入退役。

## 14. 遗留退役

退役检查：

- 所有消费者和依赖已清零并有流量证据；
- 历史、审计、许可、保存和法定冻结满足要求；
- 新系统已通过业务周期和 DR；
- 旧系统数据有可读取归档与检索方式；
- 账号、证书、密钥、网络、DNS、Topic、Cron 和备份被受控回收；
- 商业许可证/供应商终止和资产处置完成；
- 退役 Action 有 Maker-checker 和不可变记录。

不要为了“可回退”无限期维持双系统；长期双跑会产生语义分叉和更高风险。
