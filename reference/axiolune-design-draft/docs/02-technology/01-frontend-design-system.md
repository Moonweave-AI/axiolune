# 前端、视觉与交互设计

## 1. 前端架构

### 1.1 推荐栈

- TypeScript 严格模式；
- React + Vite；
- TanStack Router 负责类型化路由和深链；
- TanStack Query 负责服务端状态、缓存、失效和重试；
- Zustand 只保存局部交互/布局状态；
- React Hook Form + Zod 负责表单和契约校验；
- Storybook 维护组件、对象视图与状态样例；
- Vitest、Testing Library、Playwright 和 axe 做单元、组件、端到端与可访问性测试；
- pnpm workspace + Nx 管理应用、组件和生成 SDK。

现有网页资源显示 Umi、React 和 Ant Design Pro 体系痕迹。迁移时可保留页面壳和低风险组件，先建立适配层，再逐模块迁移；不要求一次重写。

### 1.2 应用组织

```text
apps/
├── workspace-web
├── research-web
├── execution-risk-web
├── ontology-studio-web
└── operations-web
packages/
├── design-tokens
├── ui-components
├── object-views
├── chart-specs
├── action-forms
├── auth-client
├── realtime-client
└── generated-osdk
```

这些应用共享设计系统和对象 SDK，但按安全域和发布风险独立部署。首期不采用运行时微前端；若未来多团队独立发布成为实证瓶颈，再评估 Module Federation。

## 2. 信息架构

一级导航固定为：

1. 工作台
2. 数据与资讯
3. 量化研究
4. 主动投研
5. 组合与执行
6. 风险与合规
7. 产品与经营
8. 本体与自动化
9. 平台运维

全局顶栏提供：

- 对象/命令搜索；
- 环境标识；
- 数据新鲜度与系统状态；
- 待办与告警；
- 最近对象与收藏；
- 帮助、权限申请和用户入口。

左侧导航只表达稳定能力；页面内部通过对象、保存视图和任务上下文切换，不把每种指标组合固化为菜单。

## 3. 对象化体验

每个核心对象复用统一详情框架：

- Header：名称、类型、状态、稳定标识、环境、收藏和可用动作；
- Summary：关键指标及其时间、来源和质量；
- Timeline：事件、动作、版本和评论；
- Relationships：账户—组合—策略—订单—成交等链接；
- Analysis：对象专属图表和指标；
- Evidence：来源、文档、引用和血缘；
- Access：权限、标记和申请路径；
- History：变更、审批、外部回执和审计。

对象可以从新闻、告警、表格、图、报告和 Agent 引用深链进入同一视图，避免不同模块呈现不同真相。

## 4. 视觉系统

### 4.1 字体

| 用途 | 字体 |
| --- | --- |
| 中文 UI 与正文 | `Noto Sans SC` / 思源黑体，系统无字体时回退到系统中文无衬线 |
| 拉丁字符和数字 | `Inter`，金融数字启用 tabular nums |
| 代码、标识与日志 | `JetBrains Mono` / `SFMono-Regular` |
| 报告长文 | UI 仍保持无衬线；导出报告可单独使用思源宋体 |

正文 14 px、密集表格 13 px、辅助信息 12 px；标题使用 16/20/24/32 px 四级。不能通过 10–11 px 字号容纳过多列。

### 4.4 布局与密度

- 8 px 基础网格；
- 顶栏 48–56 px，左栏展开 240–264 px；
- 默认内容最大宽度不限制大表，但说明性页面控制在 1440 px；
- 面板支持舒适/紧凑两种密度；
- 表格行高建议 36/44 px，实时监控可 32 px；
- 图表与表格共存时使用可调整 Split Pane；
- 关键指标不使用大量同质 KPI 卡，优先按任务组织。

## 5. 表格设计

附件大量页面是高维数据表。统一表格必须支持：

- 服务端过滤、排序、分组、聚合与游标分页；
- 虚拟滚动、冻结列、列选择、列宽与保存视图；
- 字段定义、单位、来源、时间和质量的悬浮信息；
- 行对象深链、行内动作和批量动作；
- 实时更新高亮但不打断阅读，支持暂停/恢复；
- 数值右对齐、文本左对齐、状态居中；
- 千分位、精度、币种和百分比由 ValueType 控制；
- 导出前显示范围、字段、权限、脱敏和预计大小；
- 超宽监控表提供列组、角色预设和详情抽屉，不一次展示全部字段。

## 6. 图表与分析交互

- 所有图表显示数据区间、时区、更新点、复权/不复权、单位和来源；
- 时间刷选同步联动表格、对象和其他图；
- 选中数据点可进入对象/证据，而不是只显示 tooltip；
- 支持保存为分析视图，并记录指标版本；
- 因子和回测图明确样本空间、调仓、费用、基准和置信区间；
- 期指基差同时显示合约、现货代理、滚动窗口、均值和 0.5–3σ 阈值；
- 实时行情断线、延迟或切源必须在图上显式提示。

## 7. 动作与审批交互

动作表单由 `ActionType` 元数据生成并允许专门组件覆盖。高风险动作使用：

1. 参数输入与即时校验；
2. 影响预览；
3. 风险/权限判定；
4. 审批或二次确认；
5. 可追踪执行进度；
6. 结果、外部回执和下一步。

不使用简单 toast 宣告异步订单或风控动作“成功”。UI 区分已受理、审批中、执行中、外部未知、已完成、部分完成、失败和已补偿。

## 8. 实时与异常状态

每个实时页面固定展示：

- 连接状态；
- 最新业务事件时间；
- 平台处理延迟；
- 当前数据源；
- 丢包/乱序/回补状态；
- 用户是否暂停刷新；
- 降级能力和恢复建议。

错误页面提供 `trace_id`、受影响对象、可重试性和支持入口，但不泄露内部堆栈或秘密。

## 9. 可访问性与国际化

- 目标满足 WCAG 2.2 AA 的相关要求；
- 全部核心流程可键盘操作；
- 图表提供表格/摘要替代；
- 焦点、错误和状态不只靠颜色；
- 时间、数字、币种、交易日与市场名称使用 locale；
- 中文术语为展示名，稳定 API 名保持英文且不可随展示文案变更。
