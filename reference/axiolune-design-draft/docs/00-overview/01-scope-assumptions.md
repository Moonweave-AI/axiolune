# 设计范围、假设与边界

## 1. 已知输入

本次设计基于以下材料：

- 附件 Markdown 中记录的工作台、数据资讯、算法交易、RMS、OMS/IMS、量化投研、主动投研和产品报表需求；
- 109 张页面截图；
- 2 份仿真环境的订单与持仓 CSV；
- AI 景气度仪表盘的静态网页资源；
- 2026-07-27 可访问的 Palantir Foundry/AIP 官方文档信息架构与相关技术页面；
- 数据、交易、知识表示、安全和软件工程领域的官方标准及项目文档。

附件更接近一次现状盘点，而非完整需求规格。因此，本方案同时给出：

- 能从材料直接确认的需求；
- 为形成完整系统而补充的必要平台能力；
- 需要在立项阶段由业务和合规确认的假设。

## 2. 业务范围假设

初始范围按中国境内机构投资管理平台设计，优先支持：

- A 股、港股、场内基金、股指期货等附件已出现或可直接推断的资产；
- 产品—资金账户—资产单元—策略—目标—订单—成交—持仓—风险的完整链路；
- 实盘、仿真、回测和场景分支相互隔离；
- 研究、组合、交易、风控、产品、数据、运维和管理岗位；
- 中文为主、英文术语与代码并存的桌面 Web 应用；
- 私有化或受控云部署。

以下内容保留扩展位，但不在首期承诺内：

- 超低时延共址交易与 FPGA 路径；
- 柜台清算核心替换；
- 全量客户账户、支付、信贷或银行核心；
- 面向公众的零售交易终端；
- 直接执行法定合规结论的无人 Agent；
- 一次性覆盖所有境外市场和全部另类资产。

## 3. 架构边界

### 3.1 平台是控制与协作系统，不替代交易所或券商真源

交易所、柜台、券商、托管、估值和会计系统仍各自保有法定或业务真源地位。平台通过来源优先级、核对和双时间模型构建“当前可操作视图”，但不能静默覆盖来源差异。

### 3.2 本体层不吞并所有数据库

本体层保存类型、关系、动作、函数、策略、对象索引和解析规则，并向应用提供统一对象视图。逐笔行情、文档原件、向量索引、图投影和订单事务数据仍驻留在专用存储。本体使用稳定标识和版本化映射把它们连接起来。

### 3.3 分析与交易的计算隔离

研究回测可以使用大规模弹性计算和最终一致的数据资产；订单、风险和审计链必须使用可预测延迟、强一致或明确状态机。两者共享语义契约，不共享故障域。

### 3.4 AI 默认不拥有越权能力

Agent 的读权限不得超过调用主体，工具权限必须显式列入白名单。发布研究、修改风险规则、提交订单、解除限制等动作默认由 Agent 生成提案，经策略检查和人工审批后执行。

## 4. 需要正式确认的关键问题

| 类别 | 待确认问题 | 对设计的影响 |
| --- | --- | --- |
| 组织 | 单法人、集团多法人，还是外部客户多租户？ | 租户隔离、数据主权、权限继承和成本模型 |
| 交易 | 哪些市场、柜台、算法商与协议必须首期接入？ | 网关数量、认证、容量与验收环境 |
| 性能 | 峰值逐笔/委托吞吐、账户数、活跃用户和报表窗口？ | 分区、集群规模、缓存和 SLA |
| 真源 | 持仓、净值、产品、证券主数据的权威来源分别是谁？ | 主数据仲裁和对账流程 |
| 合规 | 等保级别、数据分类分级、跨境、保存期与审计要求？ | 部署拓扑、加密、日志与灾备 |
| 模型 | 哪些模型能进入生产动作，谁负责模型风险？ | 模型门禁、解释、监控与审批 |
| 采购 | 是否允许商业数据库、AG Grid、Neo4j、K 线组件等？ | 许可、成本、可替代性和交付速度 |
| 云环境 | 自建机房、国产云、混合云或专有云？ | 对象存储、KMS、容器与运维选型 |

## 5. 非目标

本方案不：

- 将截图像素级复刻为最终设计；
- 把现有菜单名直接变成微服务名；
- 用大模型替代确定性风控和订单状态机；
- 让图数据库同时承担事务、时序、文档和向量全部负载；
- 在未取得正式容量与法规输入时承诺绝对性能或法律合规；
- 在设计文档中传播附件中的秘密、账号或内部地址。

## 6. 设计完成标准

本方案只有在下列关系均被清楚定义时才算完整：

1. 每项原始需求可追踪到新模块或明确退役决定；
2. 每个模块使用哪些本体对象、函数和动作；
3. 每个本体对象来自哪些数据资产并由谁负责；
4. 每个动作由谁发起、如何授权、是否审批、如何幂等和审计；
5. 每类负载进入哪一种存储和计算路径；
6. 关键风险如何监控、恢复、降级和复盘；
7. 交付阶段如何用纵向业务闭环验收，而非只验收组件是否部署。
