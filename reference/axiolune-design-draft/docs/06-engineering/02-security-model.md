# 安全、权限与审计模型

## 1. 安全目标与边界

平台按零信任、最小权限、职责分离和可证明审计设计。安全控制覆盖：

- 人、服务、设备、Agent 和外部系统身份；
- 数据源、数据产品、本体对象/属性/链接；
- 函数、指标、模型、动作、工作流和导出；
- 开发、仿真、回放、生产与灾备环境；
- 浏览器、API、消息、数据库、搜索、图、向量和媒体；
- 构建、发布、运维、备份、恢复和退役。

“能访问 Kafka/数据库”不等于“能读取全部业务数据”；“能看到对象”也不等于“能执行对象动作”。

## 2. 数据与动作分级

### 2.1 数据分类

平台同时保存两个不能混为一谈的维度：

1. **监管/业务数据级别**：按 2026《金融信息服务数据分类分级指南》和最终适用规则映射为 `核心、重要、敏感一般、常规一般`；
2. **内部保密级别**：用于日常访问和披露控制的 `Public、Internal、Confidential、Restricted`。

同一对象可以是“重要 + Restricted”；策略取两个维度及用途、地域、对象关系中的最严格控制。初始内部保密分类建议：

| 级别 | 示例 | 默认控制 |
| --- | --- | --- |
| Public | 已批准公开的产品资料 | 完整性、发布审批 |
| Internal | 一般内部配置和运营数据 | 企业身份、最小权限 |
| Confidential | 研究、组合、账户、合同、非公开报告 | 对象/属性控制、加密、导出审批 |
| Restricted | 交易指令、持仓细节、身份信息、密钥、监管限制数据 | 强隔离、双人审批、字段加密、重点审计 |

最终分级必须由法务、合规、数据安全团队按组织主体、业务牌照、部署地域和 2026 年适用规则建立“数据项—级别—用途—保存—出境—控制—证据”矩阵。

### 2.2 动作风险

| 风险级别 | 示例 | 默认处理 |
| --- | --- | --- |
| L0 只读 | 查询对象、查看公开报告 | 策略允许即可 |
| L1 可逆低风险 | 保存视图、创建个人草稿 | 单人、完整审计 |
| L2 业务变更 | 发布研究、修改主数据 | Maker-checker 或抽样复核 |
| L3 高风险 | 下单、风险例外、账户启停、生产切源 | 双人复核、强认证、额度/时窗 |
| L4 特权/系统性 | 授权策略、密钥恢复、全局本体发布、DR 切换 | 多角色批准、受控窗口、全程监控 |

风险级别是 ActionType 元数据，策略可根据金额、对象分类、影响范围和环境动态提升，不可由调用者降低。

## 3. 身份与会话

### 3.1 人员身份

- 对接企业 IdP，使用 OIDC/SAML、MFA 和条件访问；
- HR/组织系统驱动入职、转岗、离职；离职/高风险变更近实时撤权；
- 禁止共享账号；岗位账户必须映射到实际操作者；
- 高风险动作要求近期强认证，敏感会话短时有效；
- 设备合规、网络区、地理异常和风险信号进入策略上下文；
- Break-glass 身份离线保管、双人启用、短时授权、实时告警和事后复核。

### 3.2 服务与工作负载

- Kubernetes/主机工作负载使用短期身份和 mTLS 证书；
- 每个服务、环境和用途独立身份，不复用人的令牌；
- OAuth client 使用最小 scope、受限回调和自动轮换；
- 柜台/供应商静态凭据无法避免时，存于 Vault/HSM，限制网络与进程读取，缩短轮换周期；
- Notebook、CI runner、Agent 与生产服务使用不同信任域。

### 3.3 委托

用户通过应用或 Agent 触发动作时，审计同时保留：

- 原始主体；
- 调用应用/Agent/服务；
- 委托链与 scope；
- 用途和环境；
- 生效策略版本；
- 最终执行工作负载。

服务间传递签名的最小授权上下文，不无限转发原始用户令牌。

## 4. 授权决策

### 4.1 组合模型

平台组合使用：

- **RBAC**：岗位基础能力，例如研究员、交易员、风险经理；
- **ReBAC**：OpenFGA 或 SpiceDB 表达用户—团队—产品—组合—账户—对象关系；
- **ABAC**：OPA 处理分类、目的、环境、时间、设备、金额、动作参数和风险；
- **物理执行控制**：PostgreSQL RLS/列策略、OpenSearch ACL、图/向量过滤、对象存储策略和 Topic ACL。

统一请求：

```json
{
  "subject": {"id": "u123", "roles": ["TRADER"], "teams": ["desk-a"]},
  "action": "SubmitParentOrder",
  "resource": {"type": "TradingAccount", "id": "acct-7", "version": 11},
  "environment": "PRODUCTION",
  "purpose": "TRADE_EXECUTION",
  "attributes": {
    "instrument_classification": "CONFIDENTIAL",
    "notional": "12000000.00",
    "currency": "CNY",
    "device_trust": "MANAGED",
    "current_session": "CONTINUOUS"
  }
}
```

决策返回 `allow/deny`、原因 code、匹配规则、策略版本、义务（脱敏、审批、水印、数量上限）和 TTL。领域服务负责执行义务，不能只读取布尔值。

### 4.2 默认规则

- 默认拒绝；未分类资源按更严格级别处理；
- 环境、用途和对象关系均必须匹配；
- 派生数据继承输入中最严格的限制；
- 链接查询检查边及两端；图路径逐跳授权；
- 文档 chunk、OCR、embedding 和摘要继承原件 ACL；
- 聚合设置最小群体和防差分推断规则；
- 缓存、索引、下载和备份不削弱源权限；
- Agent 有效权限为“发起主体权限 ∩ Agent 工具白名单 ∩ 场景策略”。

### 4.3 一致执行点

| 层 | 责任 |
| --- | --- |
| Gateway | 认证、租户/组织、粗粒度 scope、限流 |
| Object/Action API | 对象、属性、链接、函数和动作决策 |
| 领域服务 | 业务不变量、参数义务、最终授权防线 |
| 数据层 | RLS/列、ACL、凭据隔离，防绕过 |
| Search/Graph/Vector | 查询前过滤，禁止检索后裁剪作为唯一措施 |
| Export/Media | 字段、数量、用途、水印、签名 URL 和到期 |
| UI | 可解释反馈；不作为安全边界 |

## 5. Maker-checker 与职责分离

### 5.1 通用规则

- Maker 不能批准自己的请求；
- Approval 对规范化请求摘要、对象版本、环境和有效期绑定；
- 请求参数或对象版本变化使旧审批失效；
- 批量审批展示全部影响或分层抽样规则，不以一个模糊按钮掩盖范围；
- Approver 必须对目标资源和动作有独立授权；
- Agent、服务账户和临时身份不能成为最终 Checker；
- 紧急豁免有更短有效期、补偿控制和自动复核任务。

### 5.2 典型职责矩阵

| 动作 | Maker | Checker | 执行者 | 禁止组合 |
| --- | --- | --- | --- | --- |
| 发布因子/模型 | 研究员 | 独立研究评审/模型风险 | 发布服务 | 作者自批 |
| 修改证券主数据 | Data Steward | Domain Owner | 主数据服务 | 来源维护者自批重大合并 |
| 大额下单/例外 | 交易员 | 风控/授权主管 | OMS | 同一人既放宽限额又下单 |
| 账户/网关启停 | 运维 | 业务 Owner + 安全（高风险） | 受控运维动作 | 共享管理员直接执行 |
| 授权关系变更 | 资源 Owner | Security/Compliance | IAM 服务 | 被授权人自批 |
| 本体 major 发布 | Ontology Architect | Domain + Security + Platform | 发布控制器 | 设计者单独发布 |
| DR 切换 | Incident Commander | 业务连续性负责人 | SRE | 单人无演练切换 |

## 6. 密钥、秘密与加密

### 6.1 密钥层级

- HSM/KMS 管理根密钥和 Key Encryption Key；
- Envelope Encryption 为数据域/租户/用途生成 Data Encryption Key；
- 数据库、对象、消息、备份、制品和传输分别设置密钥与轮换；
- Restricted 字段按需令牌化或字段级加密；
- 密钥访问策略与数据访问策略分离，应用只获得完成任务所需的解密能力。

### 6.2 秘密生命周期

`申请 → 批准 → 生成 → 短期分发 → 使用观测 → 轮换 → 吊销 → 证明销毁`

- 禁止把密码、Token、证书私钥写入 Git、镜像、Markdown、CSV、日志、前端或 Notebook；
- 使用 Vault/Secret Manager、CSI/sidecar 或短期动态凭据；
- CI 执行提交、历史、制品和镜像 Secret Scan；
- 读取秘密有独立审计，异常批量读取立即告警；
- 轮换同时验证消费者恢复；吊销后检查历史使用；
- 附件中出现过明文凭据，因此进入迁移前必须完成轮换、撤销旧值和使用记录调查。

## 7. 网络与运行隔离

- 办公接入、应用、数据、交易、研究、管理和外联区分段；
- 默认拒绝东西向和 egress；以工作负载身份和明确目的放行；
- 交易关键服务不接受个人工作站直连；
- 文件、PDF、图片、音视频进入非可信处理区，执行恶意检测、格式验证和沙箱解析；
- Notebook 不能访问生产交易凭据或直接写生产对象；
- 生产、Replay、Simulation 的网络、证书、账户和 Topic 隔离；
- 管理动作通过审计 API/堡垒路径，不以共享 SSH 和手工进程命令作为常态。

## 8. 审计证据模型

审计事件是不可变业务证据，不等同于应用日志。最少字段：

- `audit_id`、event/recorded time、环境；
- 原始主体、委托链、设备/会话和认证强度；
- purpose、资源/对象/属性/动作、影响范围；
- 规范化参数摘要和敏感字段掩码；
- 策略决策 ID/版本、允许/拒绝理由和义务；
- Maker、Checker、审批内容和有效期；
- 变更前后引用、领域事件、外部回执；
- 代码、本体、规则、模型、配置和数据快照版本；
- trace/correlation/action ID；
- 完整性哈希、存储位置、保留和法定冻结。

审计管线写入高吞吐检索存储，并将规定记录归档到 WORM/Object Lock。审计访问、查询和导出同样被审计；时间源同步与签名链用于证明完整性。

## 9. 数据生命周期与外发

- 采集时登记目的、合法依据、分类、地域、Owner 和保留期；
- 处理使用目的绑定，二次使用需重新评估；
- 非生产环境使用合成或不可逆脱敏数据；
- 导出前估算对象/字段/分类/接收方/保存期，执行审批、脱敏、水印、加密和短期下载；
- 分享只共享视图定义，接收者仍按自身权限查询；
- 到期删除覆盖 OLTP、湖仓、搜索、图、向量、媒体、缓存和可删除备份；
- 法定冻结优先于普通删除并记录依据；
- 跨境、外包和第三方传输由合规核验，不由技术团队默认放行。

## 10. AI 与检索安全

- 权限裁剪在检索前执行，chunk/embedding 继承文档 ACL；
- 不可信内容与系统指令、工具描述和用户提示分区；
- 对提示注入、恶意文件、工具注入、数据投毒和越权链接做检测；
- 模型输出不是授权依据；所有副作用进入 Action Service；
- 高风险 Agent 默认只生成 `ActionProposal`，人工审阅证据、参数和影响；
- 输出必须引用可访问证据，缺失或冲突时拒答/标记不确定；
- 对模型、提示、检索配置、工具和评测集做版本和审计；
- 禁止向外部模型发送未经批准的 Confidential/Restricted 数据。

## 11. 安全开发与供应链

- 威胁建模覆盖身份、信任边界、数据流、滥用场景和恢复；
- SAST、DAST、SCA、IaC、容器、Secret、许可证与恶意依赖扫描；
- 依赖锁定、内部镜像源、SBOM、签名制品和 provenance；
- CI 与运行环境分离，构建身份不能直接部署生产；
- Admission Policy 校验签名、来源、最小权限、只读根文件系统、网络和资源上限；
- 漏洞按暴露、可利用性、业务影响和补偿控制确定修复时限；
- 第三方 SDK、行情/券商连接器和模型制品执行安全与许可评审。

## 12. 安全测试矩阵

| 范围 | 必测场景 |
| --- | --- |
| IAM | 入转离、MFA、Token 过期/撤销、服务身份轮换 |
| Object | 行/列/单元、链接两端、时间/用途/环境变化 |
| Action | 自批、审批失效、陈旧版本、额度提升、重放 |
| Search/Graph/Vector | 越权发现、推断、缓存污染、路径泄漏 |
| Export/Media | 大批量、隐藏字段、签名 URL、过期和转发 |
| API/Event | IDOR、注入、重放、伪造主体、敏感日志 |
| AI | Prompt/tool injection、越权检索、错误引用、危险提案 |
| Platform | 容器逃逸、供应链、网络绕过、Break-glass |
| Recovery | 密钥丢失/轮换、备份解密、审计完整性 |

## 13. 安全运营

- SIEM 汇聚认证、授权拒绝、敏感读取、导出、策略/密钥/本体变更和供应链事件；
- UEBA/规则识别异常时间、设备、对象数量、连续拒绝、批量下载和权限提升；
- P0/P1 安全事件自动冻结相关短期令牌和高风险动作，但避免无评估地停掉全部交易；
- Incident Response 保存证据、限定范围、轮换凭据、通知责任方和满足适用报告要求；
- 权限按季度复核，特权/外部/临时权限更高频；
- 策略、密钥恢复和 Break-glass 至少半年演练，并跟踪改进项关闭。
