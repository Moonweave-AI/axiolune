# 源材料处理与证据边界

## 1. 最小化原则

本交付包仅保留经过脱敏的资产级元数据、需求追踪和结构性结论。原始截图、订单/持仓明细、编译资产、个人头像、内部链接、账号、网络地址和任何秘密均不复制。

## 2. 证据等级

| 等级 | 含义 | 可支持的结论 |
| --- | --- | --- |
| 明示 | 需求 Markdown 直接写明 | 页面名、字段名、部分算法说明与运维现状 |
| 截图 | 可见 UI 和数据结构 | 布局、交互、显示字段、视觉模式 |
| 资产 | HTML/JS/CSS/导出结构 | 前端栈、路由/API 线索、字段类型与数据质量 |
| 推导 | 多项证据与工程原则组合 | 目标域、服务边界、技术选型和迁移方案 |
| 待确认 | 材料无法证明 | 权限、SLA、正式公式、规则优先级、许可和监管适用性 |

推导不能覆盖待确认项；实施时应把业务访谈和 PoC 结论追加为新的 Evidence 与 Decision 对象。

## 3. 安全处置

1. 轮换附件中暴露或可能暴露的秘密，并检查历史使用日志；
2. 禁止把真实秘密写入 Markdown、CSV、前端 bundle、镜像、Issue 或示例配置；
3. 对原附件设置最小访问、下载水印、审计、保留期和 DLP；
4. 将个人信息、交易数据、源代码和系统拓扑分别分类分级；
5. 未来需求材料使用合成数据、遮罩账号和不可反推的截图；
6. 安全团队决定原附件是否作为事件证据进入 legal hold。

## 4. 可重复审计

`evidence/attachment_inventory.csv` 提供资产 ID、相对路径、类型、尺寸、来源章节、页面/功能、摘要、风险和审阅状态。它可以证明覆盖范围，但不能替代原件的保管、hash、访问日志与合法授权。
