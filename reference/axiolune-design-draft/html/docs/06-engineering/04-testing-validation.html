测试、验证与发布质量门

1. 测试目标

金融平台测试必须证明的不只是“代码执行了”，还包括：

  • 业务状态机和财务恒等式正确；
  • 点时数据、市场日历、单位和精度正确；
  • 权限、审批和用途在所有访问通道一致；
  • 重试、重复、乱序、外部未知和恢复不会产生额外副作用；
  • 本体、数据、API、事件、模型和 UI 版本兼容；
  • 在峰值、故障、降级和灾备下仍能达到已承诺目标；
  • 结果、动作和发布可审计、可复现、可核对。

2. 测试环境与数据

环境 数据 主要用途 禁止项
Local/Dev 合成、小型固定数据 快速单元/组件 真实生产秘密和受限原始数据
Integration 合成 + 受控脱敏样本 服务、契约、管线 实盘外部副作用
UAT 点时脱敏快照 业务流程和体验验收 实盘凭据
Replay 生产历史事件的受控副本 算法、容量、故障和回归 向生产通道写入
Simulation 独立仿真账户/行情 OMS/RMS、算法执行 与生产账户混用
Pre-production 生产同构、最小数据 发布与恢复验证 长期存放生产数据
DR 加密复制/恢复数据 切换和恢复演练 未批准双写生产

测试数据工厂生成证券、日历、行情、订单、成交、持仓、现金、报告、关系与权限。样本应覆盖停牌、涨跌停、复权、公司行动、跨日/夜盘、部分成交、乱序回报、负价格可能性、精度边界、退市和标识变更。

3. 测试金字塔与责任

层 内容 主要责任 运行频率
静态/生成 类型、Schema、lint、架构、策略 开发/平台 每提交
单元/属性 领域规则、函数、状态机、数学不变量 开发/量化 每提交
组件 数据库、消息、策略、工作流、适配器 开发 每合并
契约 API、事件、数据、本体、外部协议 Provider + Consumer 每合并/发布
集成 跨服务 happy/error path QA/开发 每日/候选版本
E2E 角色旅程、审批、下单、报表 QA/业务 候选版本
Replay/Simulation 历史重放、行情与柜台行为 交易/量化/SRE 候选/定期
非功能 性能、安全、韧性、恢复 SRE/安全/QA 发布门/定期
业务验收 语义、口径、操作、证据 Domain Owner 每能力

E2E 数量应少而关键；大量边界通过单元、属性、模型和契约测试更稳定地覆盖。

4. 领域与状态机测试

4.1 聚合不变量

  • ordered_qty = filled_qty + cancelled_qty + remaining_qty（按具体状态定义）；
  • 成交、撤单和拒绝不能使数量为负或超出委托；
  • 聚合版本严格单调，同一命令幂等；
  • 已结束订单不能无合法动作回到执行态；
  • 资金/持仓可用量与冻结/释放相互核对；
  • 风险规则超时按 fail-open/fail-closed 的预先声明处理；
  • 审批绑定请求摘要和对象版本；
  • 场景动作不能产生生产副作用。

使用 property-based testing/模型测试随机生成事件序列，验证所有可达状态，而不是只写正常路径样例。

4.2 外部适配器

  • 来源序号缺口、重复、乱序和重连；
  • 同一外部订单不同回报顺序；
  • 网络超时但请求已成功；
  • 限流、半连接、证书轮换和协议错误；
  • 主备源切换和不同字段语义；
  • 供应商新增未知枚举；
  • 市场开闭市、午休、夜盘和时区。

供应商模拟器保留协议黄金报文；真实联调只补充而不替代自动测试。

5. API、事件与工作流

5.1 API

  • OpenAPI/GraphQL/Proto 静态兼容；
  • 消费者驱动契约；
  • 游标稳定、分页无重无漏；
  • 金额精度、19 位 ID、时区、null/zero/unknown；
  • 幂等键同请求/异请求、并发和过期；
  • ETag/expected_version 冲突；
  • 批量部分失败和异步任务取消；
  • 速率限制、超时、背压和大结果；
  • 不同角色/用途/环境的负向授权。

5.2 事件

  • Schema 新旧消费者兼容；
  • 重复、乱序、缺口、迟到和坏消息；
  • Outbox relay 崩溃前后；
  • Inbox 与业务事务原子性；
  • 消费者积压和恢复；
  • DLQ 修复/重放不触发重复副作用；
  • Replay 与实时 Topic 隔离；
  • PII/Restricted 字段未意外进入 payload。

5.3 Saga/工作流

对每一步故障做组合测试：

  • 调用前、调用中、回执后崩溃；
  • 超时后外部状态未知；
  • 补偿成功、失败、超时或业务上不可补偿；
  • 审批过期、撤回、对象版本变化；
  • Worker 重启、工作流版本升级；
  • 人工任务超时和升级；
  • 多次信号/回调重复。

确定性工作流使用版本化 API，历史实例必须能在代码升级后继续执行或迁移。

6. 数据、时间与血缘测试

6.1 数据契约

  • Schema、类型、可空、单位、币种、精度和枚举；
  • 主键唯一、外键/链接完整、来源优先级；
  • 行数、分布、范围、重复和异常；
  • 新鲜度、到齐时点、迟到/回补；
  • Data Owner、分类、保留和许可；
  • 数据—对象—函数—应用血缘完整。

失败资产进入隔离区，不能仅发告警后继续发布。

6.2 点时正确性

测试查询只使用当时可知信息：

  • valid_time 与 system_time/knowledge_time 分开；
  • 财报使用实际披露时间而非报告期末；
  • 指数成分、行业分类、证券状态和借券可用随时间变化；
  • 公司行动、复权因子和币种汇率有版本；
  • 训练/回测快照不可被后续修订静默覆盖；
  • 随机截断历史并检测结果是否使用未来数据。

6.3 核对

建立订单、成交、持仓、资金、净值和报告的黄金核对集：

  • 逐记录匹配与聚合控制总数；
  • 金额/数量/费用容差按类型定义；
  • 差异分类为时间差、映射、精度、缺失、重复、业务异常；
  • 自动修复必须是受控 Action；
  • 截止点要求 100% 覆盖，未解释差异阻止相关发布/结算。

7. 量化、风险与模型验证

7.1 因子与回测

  • 因子清洗、标准化、中性化使用手算黄金样例；
  • IC/RankIC/ICIR、分组收益、换手和衰减对边界数据校验；
  • 可交易股票池按点时构建；
  • 停牌、涨跌停、成交量、费用、滑点和容量约束；
  • 事件在可得时点之后才允许成交；
  • 多实现差分测试和历史版本回归；
  • 输出绑定代码、参数、数据快照和环境。

7.2 风险

  • 限额边界前后一单位；
  • 多币种、净/总敞口、衍生品和缺失价格；
  • VaR/ES 的窗口、置信度、样本和回测；
  • 压力场景复算、传播路径和不可用输入；
  • 规则优先级、例外范围、到期和冲突；
  • 风控服务延迟/不可用时的明确降级。

7.3 AI/ML

  • 离线评测：准确、召回、校准、稳定、偏差和分群；
  • 时间外/市场状态外验证，避免随机切分泄漏；
  • 在线影子、A/B 或金丝雀，预先定义停止条件；
  • 数据/概念漂移、延迟、成本和回退；
  • 文档引用支持度、拒答和不确定性；
  • Prompt/tool injection、越权检索和危险工具；
  • 人工审批不被默认按钮或界面诱导架空。

模型结果测试不能替代业务规则和权限测试。

8. 权限与安全验证

用 {subject × role/team × object relation × property × action × purpose × environment × time} 生成决策矩阵。至少覆盖：

  • 同角色不同产品/账户；
  • 权限刚授予、到期、撤销和关系变化；
  • 链接一端不可见；
  • 派生指标混合不同分类；
  • 搜索、图、向量、缓存和导出；
  • Maker 尝试自批、审批参数被修改；
  • Agent 权限与用户交集；
  • Break-glass 启用与到期；
  • IDOR、注入、重放、CSRF、SSRF、文件和供应链风险。

OPA 策略单元测试、OpenFGA/SpiceDB 模型测试、服务端集成测试和端到端负向测试缺一不可。

9. 前端与可用性

  • 关键角色旅程和键盘操作；
  • 1k/10k/100k 虚拟表格、列固定和服务端过滤；
  • 实时断线、恢复游标、延迟/来源展示；
  • 加载、空、无权限、部分数据、降级和错误状态；
  • 涨跌、风险不只靠颜色；WCAG 对比度和辅助技术；
  • 中文/英文、长文本、数字、时区和不同屏幕；
  • 视觉回归使用稳定组件/Token，不把动态行情当像素黄金；
  • 用户误操作：批量选择、危险确认、撤销和刷新并发。

10. 性能、容量与韧性

10.1 性能

  • 单组件基准定位序列化、SQL、策略和网络预算；
  • 端到端负载按真实对象大小、权限过滤和缓存命中率；
  • 1×、2×、5× 峰值及突发；
  • soak test 检查内存、句柄、碎片、积压和 compaction；
  • 交易路径记录 P50/P95/P99/P99.9 与最大值；
  • 分析大查询、导出和图遍历必须遵守资源/节点/时间预算。

10.2 混沌与故障注入

  • Pod/节点/可用区故障；
  • 网络延迟、丢包、分区和 DNS；
  • PostgreSQL 主从切换、Kafka broker/ISR、对象存储错误；
  • ClickHouse/OpenSearch/向量不可用；
  • 外部行情/柜台超时和错误；
  • KMS/Vault/IdP 短时不可用；
  • 时钟偏差、证书到期和磁盘满；
  • 数据质量失败和错误 Schema。

先在 Integration/Replay 演练，有护栏后再在生产做小范围受控实验。

11. 备份、恢复与 DR 测试

  • 备份任务成功不等于可恢复；执行定期隔离恢复和内容校验；
  • PostgreSQL 验证 PITR 到指定业务时间；
  • Kafka/湖仓验证事件重放和业务去重；
  • 搜索/图/向量验证从权威源重建；
  • KMS/Vault 验证分权恢复和解密；
  • 全链路 DR 验证 DNS/路由、IdP、证书、外部白名单、数据一致和切回；
  • 记录实际 RPO、RTO、数据差异、手工步骤和改进项；
  • DR 环境恢复后先只读核对，再按批准顺序开放动作。

12. 发布质量门

风险 必须证据
L0/L1 单元、契约、权限、基本性能、可观测
L2 集成/E2E、数据/算法黄金、回滚、业务 UAT
L3 Replay/Simulation、故障/幂等/Saga、Maker-checker、容量
L4/Tier 0 独立安全/风险评审、DR/恢复、影子/金丝雀、管理批准

阻断条件包括：

  • 未解释的破坏性契约变化；
  • 权限负向测试失败；
  • 点时泄漏、金额/数量不变量失败；
  • 无法恢复的迁移或未验证备份；
  • SLO/错误预算、DR 或审计系统不健康；
  • 高风险动作无幂等/未知状态处理；
  • 关键 Owner、运行手册或支持排班缺失。

13. 测试证据

ValidationRun 记录：

  • 需求、风险、测试计划与范围；
  • 代码、本体、契约、策略、模型和数据快照版本；
  • 环境、配置、随机种子、模拟器版本；
  • 输入、预期、实际、容差和结果；
  • 日志/指标/Trace/报告引用；
  • 失败、豁免、批准人、到期和修复任务；
  • 重现命令和制品摘要。

上线后证据与 ReleaseManifest 关联，保证任一生产版本可回答“测试了什么、没测试什么、谁接受了剩余风险”。
