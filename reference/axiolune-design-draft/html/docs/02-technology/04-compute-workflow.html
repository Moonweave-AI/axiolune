流批计算、数据编排与业务工作流

1. 三种引擎各司其职

引擎 负责 不负责
Flink 事件时间流、状态、窗口、实时指标和告警 人工审批、长事务
Airflow/dbt/Spark/Trino 数据资产、批处理、质量、重算和历史分析 订单状态机
Temporal 业务长流程、重试、补偿、定时、审批和外部副作用 TB/PB 数据转换

2. Flink 实时计算

核心作业：

  • 行情去重、乱序、水位线和 K 线；
  • Level-2 盘口/逐笔特征；
  • 行情、网关、风控和订单延迟；
  • 日内持仓、现金与敞口增量；
  • 撤单率、拒单、异常流量和风险告警；
  • 对象/搜索/ClickHouse 物化事件；
  • 实时数据质量与来源切换。

每个作业定义状态 TTL、checkpoint、savepoint、升级兼容、迟到事件和回补策略。硬风控中必须同步完成的判定不依赖异步 Flink 结果；Flink 结果可作为预计算上下文。

3. Airflow 与数据资产

使用 Airflow 3 的资产感知调度与数据产品清单组织依赖，而不是维护“脚本列表”：

  • 输入/输出数据产品；
  • 分区、依赖和负责人；
  • Schema、质量检查和 SLO；
  • 代码、环境和运行参数；
  • 物化时间、快照和血缘；
  • 回填、重试和成本。

dbt 管理 SQL 模型、文档和测试；Spark 处理大规模计算；Trino 提供跨 Iceberg/数据库的交互 SQL；DuckDB/Polars 支持本地开发和小样本验证。

4. Temporal 业务工作流

典型 Workflow：

  • 数据访问申请和到期回收；
  • 风险例外审批；
  • 风险标的处置；
  • 订单提案—组合复核—合规—执行；
  • 持仓/成交/净值对账与差异处理；
  • 因子/模型发布；
  • 报告生成、复核和发布；
  • 文档抽取候选的人工确认；
  • 供应商/柜台异常切换；
  • 退役数据产品和本体资源。

Workflow ID 使用稳定业务键，Activity 设置明确 timeout、retry 和 heartbeat；人工任务以外部事件恢复，不长期占线程。所有外部调用设计幂等或补偿。

5. 规则引擎

规则按执行环境分层：

  • 交易硬规则：确定性代码/编译规则，延迟预算严格；
  • 风险/合规策略：版本化 DSL/CEL/Decision Table；
  • 数据质量：SQL/声明式检查；
  • 对象与动作权限：OpenFGA/SpiceDB + OPA；
  • 研究筛选：可版本化表达式，禁止直接写实盘状态；
  • AI 守卫：工具白名单、输出 Schema、证据和审批门。

规则定义包含适用范围、优先级、冲突处理、阈值单位、有效期、测试样例、所有者和审批。规则变更先在分支/回放数据上模拟。

6. 调度与市场日历

所有计划任务基于 TradingCalendar 和 TradingSession，而非散落 crontab：

  • 节假日、临时休市、半日市、夜盘和时区；
  • 盘前、集合竞价、连续竞价、午休、收盘和盘后；
  • 数据就绪依赖而非仅固定时间；
  • 迟到/缺失来源时的阻断、降级和通知；
  • 可追踪补跑和业务日期覆盖。

系统服务由 Kubernetes/systemd/受支持调度器管理；不以 screen、人工命令和 kill -9 作为正式运行方案。

7. 分支、回放与发布

  • 数据资产：Iceberg 快照 + 代码分支；
  • 本体/规则：版本化声明 + 分支覆盖层；
  • 应用：生成 SDK 与 feature flag；
  • 流作业：savepoint + 影子 Topic；
  • 交易/风险：历史事件重放 + 仿真柜台；
  • 业务场景：主线快照 + 有效覆盖事件。

发布门检查 Schema 兼容、下游影响、权限、质量、回放差异、容量和回滚。分支过期后自动归档，禁止长期漂移。

8. 计算成本治理

  • 每个数据资产和模型运行记录 CPU/GPU、内存、扫描字节、输出和成本；
  • 交互查询有扫描上限和取消；
  • 回填按分区和优先级排队；
  • 研究空间有配额、闲置回收和依赖缓存；
  • 重复指标由指标注册中心复用；
  • 热、温、冷数据分层；
  • 先优化数据布局与物化，再盲目扩容。
