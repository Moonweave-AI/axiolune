## ADR-011 Compliance (Single Truth Source)

**Status**: ✅ **FULLY COMPLIANT**

### Validation Results

```
✓ No Field.semanticMapping found
✓ No SemanticFieldMapping type found
✓ SemanticMappingDefinition uses SourceBinding
✓ Uses slotMappings (correct naming)
✓ ValueBinding type defined
✓ ValueBinding is discriminated union
✓ MaterializationRun type defined
✓ MaterializationRun has immutable runtime context
✓ No watermark in plan (correct)
✓ TransformationDefinition has all required fields
```

### Key Implementations

1. **Deleted Prohibited Types**:
   - `Field.semanticMapping` (violated single truth source)
   - `SemanticFieldMapping` (cannot express required semantics)
   - `TransformationReference` (replaced by versioned references)

2. **New Core Types**:
   - `SourceBinding`: Multi-table joins, filters, aggregations
   - `RowSetSpec`: Row-level operations before field mapping
   - `IdentitySpec`: Logical keys, version keys, IRI templates
   - `ValueBinding`: Union type (directField, transformation, literal, runtimeContext)
   - `SlotMapping`: Replaces FieldMapping, supports all target types

3. **Separated Runtime State**:
   - `MaterializationRun`: Immutable runtime context
   - `MaterializationPlanDefinition.watermark` moved to Run

## ADR-012 Compliance (Three-Axis Temporal)

**Status**: ✅ **FULLY COMPLIANT**

### Validation Results

```
✓ TemporalMappingSpec type defined
✓ TemporalMappingSpec has patternRef
✓ TemporalMappingSpec supports all three time axes
✓ No CURRENT_TIMESTAMP or non-reproducible time functions in config
✓ TimeAxisBinding type defined
✓ TimeAxisBinding has required 'from' field
```

### Key Implementations

1. **Three-Axis Model**:
   - `validTime`: When fact holds true in reality (business time)
   - `knowledgeTime`: When platform knows/retracts version (transaction time)
   - `availabilityTime`: When consumers can use data (regulatory time)

2. **TimeAxisBinding**:
   - Explicit `from` (required) and `to` (optional) for each axis
   - Uses `ValueBinding` (no hardcoded timestamps)
   - `closePolicy` for knowledge time version management

3. **Reproducible Queries**:
   - `MaterializationRun.assertionTime`: Immutable knowledge assertion time
   - `MaterializationRun.referenceTime`: Immutable reference for time-based queries
   - No `CURRENT_TIMESTAMP` anywhere in configuration
   - All time references use `RuntimeContextBinding`

## Breaking Changes from v0.4

|--------|------|----------------|
| Deleted `Field.semanticMapping` | BREAKING | Use `SemanticMappingDefinition` with `SourceBinding` |
| Deleted `SemanticFieldMapping` | BREAKING | Use `SlotMapping` with `ValueBinding` |
| Deleted `TransformationReference` | BREAKING | Use versioned `TransformationDefinition` with explicit inputs |
| Renamed `fieldMappings` → `slotMappings` | BREAKING | Update all mapping references |
| `sourceDataset: uri` → `source: SourceBinding` | BREAKING | Wrap dataset in SourceBinding structure |
| Removed `watermark` from plan | BREAKING | Access via `MaterializationRun.watermark` |
| `TemporalMappingSpec` complete rewrite | BREAKING | Use three-axis model with `TimeAxisBinding` |
