# RFC-009: M2 Practitioner-First Authoring Refactor

**Status**: Proposed (Phase B charter — pending ADR-034 acceptance)  
**Date**: 2026-08-07  
**Supersedes**: none (extends RFC-001 acceptance axes)  
**Related**: [ADR-034](../decisions/ADR-034-m2-practitioner-first-refactor.md), [ADR-016](../decisions/ADR-016-typed-container-authoring-profile.md), [M2-DEFINITION-STYLE-GUIDE.md](M2-DEFINITION-STYLE-GUIDE.md), [M2-SEMANTIC-QUALITY-RUBRIC.md](M2-SEMANTIC-QUALITY-RUBRIC.md)

## Problem

M2 `module.yaml` files pass machine gates but fail the primary consumer: finance domain experts. Root causes:

1. **Single flat IR** — domain semantics, assurance profiles, and Layer-4 materialization evidence share one 900–8800 line file.
2. **Mechanical definitions** — `"X, is a … used for …"` template optimized for validators, not paraphrase.
3. **False equivalence** — `approved` conflates structural conformance with practitioner comprehension.
4. **ADR-029 D6 precedent** — runtime/reproducibility profile was document-scoped only; physical separation was deferred and never delivered.

## Proposal

Phase B introduces a **multi-file module envelope** and a **practitioner definition standard** without changing public IRIs or OWL entailments during migration waves.

### 1. Module envelope (authoring split)

Each finance module directory MAY use:

| File | Concern | Reader |
|------|---------|--------|
| `module.core.yaml` | Business types, relations, constraints, CQs-facing semantics | Domain experts |
| `module.profile.yaml` | Assurance / implementation profiles (optional) | Modelers + QA |
| `module.binding.yaml` | Layer-4 source artifacts, contract refs/digests, probe locks (optional) | Data/platform engineers |
| `module.yaml` | **Merged compile artifact** (generated by `merge-module-envelope.cjs`) | Validators, OWL/SHACL generators, visualization |

Rules:

- Typed containers from ADR-016 unchanged; no new top-level keys under `domain`.
- Merge is deterministic: same fragments → same `module.yaml` bytes.
- Tools that read `module.yaml` continue unchanged until all modules migrate.
- IRI stability: split is organizational only; no identifier recycling.

### 2. Practitioner definition standard

See [M2-DEFINITION-STYLE-GUIDE.md](M2-DEFINITION-STYLE-GUIDE.md). Summary:

- **Forbidden**: opening with `"<Label>, is a"` or ending every sentence with `"used for"`.
- **Required on exported core concepts**: plain-language `definition`, practitioner `cnNote`, one positive example and one exclusion in prose (within existing fields — no new dialect keys).
- **Module header `definition`**: one paragraph business scope; engineering profile notes move to `module.profile.yaml` header comment or profile module definition.

### 3. Acceptance axis addition (RFC-001 extension)

Add **Axis 6 — Practitioner readability** (blocking for Phase B re-approval):

| Check | Pass when |
|-------|-----------|
| Blind paraphrase | ≥2 non-ontology finance reviewers paraphrase 80% of module core concepts without prompting |
| Core file size | `module.core.yaml` ≤ 40% of merged line count (target; waivable with ADR note) |
| Binding isolation | All `meta/data-binding` attributeUses live in `module.binding.yaml` after migration |
| Entry path | Module has `docs/ontology/practitioner/fin-*-guide.md` generated or maintained |

Existing axes 1–5 remain; Phase B modules carry `status: review` until axis 6 passes.

### 4. Migration waves

| Wave | Modules | Rationale |
|------|---------|-----------|
| **W0** | instruments (916 lines) | Smallest; identity + listing spine |
| **W1** | foundation, market-structure, market-data | Read path for all slices |
| **W2** | market-rules, orders-execution, portfolio-positions | Highest practitioner traffic |
| **W3** | risk, strategy-research, post-trade-operations | Largest files last |

Per wave: split → rewrite core definitions → SME gate → merge → `test-all-domain` → Round supplement.

### 5. Non-goals (Phase B)

- No FIBO full import.
- No M3 meta-type invention.
- No semantic deprecation of ADR-020–033 architecture decisions (re-home only).
- No replacement of CQ/fixture/SHACL evidence — re-packaging only.

## Open questions

1. Should `module.yaml` remain committed or become gitignored generated output? **Proposed**: remain committed until W3 completes, then CI-generated.
2. Physical module split (`fin-portfolio-runtime`) — out of Phase B scope; tracked as ADR-035 candidate.

## Decision request

Accept RFC-009 to authorize Phase B migration waves and axis 6 gate alongside [ADR-034](../decisions/ADR-034-m2-practitioner-first-refactor.md).
