# ADR-013: M3 v0.6.0 Breaking Prerequisite and Frozen M2 Upstream Baseline

**Status**: Accepted  
**Date**: 2026-08-04  
**Scope**: M3 semantic meta-model (`ontology/meta/`) — the frozen upstream baseline for M2 finance domain modules  
**Related**: RFC-001 (M2 semantic conformance), domain ADR-016 (typed-container authoring profile), M2-PLAN

---

## Context

M3 is the semantic meta-model that defines the meta-types (`OntologyModuleDefinition`, `ObjectTypeDefinition`, `AssociationTypeDefinition`, `RelationTypeDefinition`, `AttributeTypeDefinition`, `IdentifierTypeDefinition`, `CodeListTypeDefinition`, `ConstraintDefinition`, and the Layer 2–4 structures) that M2 domain modules instantiate. M2 is not a free-form taxonomy; it is a version-locked set of M3 meta-type instances. When M3 changes semantics, M2's compilation, validation, and version lock all shift with it.

The prior M3 baseline cited by M2 planning was v0.5.1. Subsequent meta-model work advanced M3 to v0.6.0 with breaking changes that affect M2 projection and validation. The four M3 source YAML files and the projected OWL (`owl:versionIRI`) are all at v0.6.0; the M2 authoring profile (domain ADR-016, typed containers) and the RFC-001 conformance contract both presume this v0.6.0 semantics. Retaining a v0.5.1 prerequisite in governance artifacts while the codebase has moved to v0.6.0 is a baseline drift: the "ruler" used to measure M2 must itself be declared and frozen.

## Decision

1. **M3 v0.6.0 is the frozen upstream baseline** for all M2 finance domain modules. The four meta-model YAML files in `ontology/meta/` (core, cross-domain-patterns, behavior, data-binding) are all at v0.6.0 and are the single source of M3 semantics.
2. **The M3 v0.6.0 breaking changes are acknowledged and incorporated**:
   - Added an explicit boolean `abstract` flag for non-instantiable `ObjectTypeDefinition` supertypes.
   - Corrected CodeList-valued `AttributeTypeDefinition` projection to `owl:ObjectProperty` and defined `sourceEvidenceRef` as a public annotation property.
   - Added strict `CodeValueDefinition` and evidence-locked code-list members.
   - Added `AssociationTypeDefinition` endpoints, `Quantity` rounding projection, and removed the deprecated `availableAt` single-instant attribute.
3. **M2 must not retain the v0.5.1 prerequisite.** M2-PLAN, AGENTS.md, and related governance artifacts bind to M3 v0.6.0. The `availableFrom`/`availableTo` availability axis (ADR-012) is canonical; `availableAt` is removed.
4. **This ADR is the authoritative version lock.** When M3 advances beyond v0.6.0, a successor meta ADR must be Accepted before M2 governance artifacts may cite a newer baseline.

## Consequences

- M2 authoring (domain ADR-016 typed-container profile), validation (`validate-m2-core`), and generation (`generate-m2-owl` / `generate-m2-shacl` / typed projection) all compile against M3 v0.6.0 semantics.
- The M3 `Schema`, SHACL shapes, and pattern injection closure referenced by M2 `patternBindings` are the v0.6.0 projections.
- Downstream visualization and tooling that read `ontology/meta/*.yaml` consume v0.6.0 content directly; no v0.5.1 fallback is maintained.
- Future M3 breaking changes require a new meta ADR before M2 may adopt them; M2 modules stay version-locked to v0.6.0 until then.
