数据与多模态架构

1. 数据产品分层

层级 内容 可变性 典型消费者
Landing 来源原包、协议消息、文件和媒体 只追加 审计、重放、取证
Raw 解析后的来源结构，保留原字段 只追加/更正另版 数据工程
Conformed 统一标识、时区、单位、代码和双时间 版本化 本体、研究、风控
Curated 主题数据产品、特征、K 线、财务与事件 版本化 应用与算法
Serving OLTP、OLAP、搜索、图、向量和对象索引 可重建 在线应用
Evidence 数据契约、质量、血缘、运行与审批证据 只追加 治理、审计

每个生产数据产品有产品所有者、技术所有者、Schema、语义、时间口径、质量 SLO、保留期、权限、下游和退役策略。

2. 流批协同

  • Kafka 承载市场、订单、成交、风险、任务与 CDC 事件；
  • Flink 根据 event time、watermark 和状态计算实时 K 线、延迟、敞口、告警和物化视图；
  • Iceberg 保存原始与规范化历史，并提供快照、Schema 演进和分区演进；
  • Spark 处理大规模历史重算、特征与训练；dbt/Trino 处理可读 SQL 资产；
  • Airflow 组织数据资产依赖、质量门和重算；Temporal 不承担大数据调度；
  • ClickHouse 消费规范化事件和发布资产，用于交互式分析。

3. 金融时间模型

所有事实至少区分：

  • event_time：市场或业务事件实际发生时间；
  • source_time：来源系统生成时间；
  • ingest_time：平台接收时间；
  • valid_from/valid_to：事实对业务世界有效的区间；
  • system_from/system_to：平台记录该版本的区间；
  • publish_time：信息首次对目标用户可见时间；
  • revision_time：来源修订时间；
  • trading_date：按市场日历归属的交易日。

关键表使用双时间或等价的不可变版本模型。禁止用数据库 updated_at 同时表示全部时间语义。

4. 主数据与身份解析

Instrument、LegalEntity、FundProduct、Account 等对象使用平台 Canonical ID；供应商代码、交易所代码、内部代码和历史代码作为带有效期的 ExternalIdentifier。

身份解析顺序：

  1. 强键精确匹配；
  2. 有效期与来源范围校验；
  3. 规则候选匹配；
  4. 概率/模型候选建议；
  5. 人工合并或拆分审批；
  6. 发布解析事件并重建受影响投影。

合并不物理删除旧 ID；保留别名、决策证据、影响对象和可逆记录。

5. 市场与 Level-2 数据

  • 分 Topic/表处理 Quote、Trade、Order、OrderBook、Auction、Status；
  • 以交易所序号和来源序号检测丢包、乱序和重复；
  • 原始 tick 永久或按政策保留，K 线和微观结构指标可重建；
  • 交易日历、集合竞价、午休、夜盘、涨跌停和合约换月是显式配置；
  • 分时、K 线、逐笔和基差统一使用 Instrument/Contract 与时间范围接口；
  • UI 订阅先经过权限、标的过滤、节流和背压。

6. 交易与持仓数据

订单事件采用追加模型，当前状态由确定性投影生成。每条外部回执保留：

  • 来源网关、会话和序号；
  • 原始状态与规范化状态；
  • 交易日、发送、接收和处理时间；
  • 原始负载哈希；
  • 对应母单、子单、账户和策略；
  • 去重键与异常状态。

持仓由日初权威快照、成交、公司行动、划拨和人工调整组成；日内投影与日终权威对账分开。差异形成 ReconciliationBreak，不直接被覆盖。

7. 文档、图片与视频

原件存入具备版本、加密和保留策略的 S3 对象存储；PostgreSQL/本体只保存 MediaItem 元数据和引用。

处理管线：

  1. 上传或接入时校验 MIME、大小、哈希与恶意内容；
  2. 保存不可变原件和来源信息；
  3. 生成预览、缩略图、分片或转码；
  4. OCR、文本抽取、版面识别、音频转写；
  5. 将页、段、时间片、框选区域建成可引用片段；
  6. 实体/事件抽取只生成带证据的候选；
  7. 全文与向量索引携带对象和 ACL；
  8. 生命周期策略处理归档、法定保留和删除。

媒体引用而非二进制副本进入对象属性，避免复制和权限漂移。该方法与 Palantir media reference 的思想一致。Using media in the Ontology

8. 数据质量

质量门分四层：

  • 接入：完整性、Schema、重复、序号、时区、文件签名；
  • 规范化：标识解析、单位、代码表、时间有效性和来源覆盖；
  • 业务：数量守恒、资金持仓平衡、价格边界、状态机和对账；
  • 研究：点时正确性、前视偏差、幸存者偏差、样本覆盖和复现。

检查结果是 QualityCheckRun 对象，包含目标资产版本、规则版本、样本、统计、失败明细、处置和豁免。失败是否阻断发布由数据产品策略决定。

9. 血缘与影响分析

血缘覆盖：

  • Source → DataAsset → Transform → PublishedAsset；
  • DataAsset → ObjectType/Property；
  • Property/Metric → Function/Model；
  • Function/Action → Application/Report/Agent Tool；
  • Ontology/Schema 变更 → 下游 SDK、应用、查询和策略。

发布前必须计算下游影响、兼容性和回填需求。血缘不能只停留在表级；核心财务、因子、风险和报表指标至少达到列/属性级。

10. 生命周期与保留

  • 原始交易、动作和审计记录使用 WORM 或等价不可变策略；
  • 派生索引可按源数据重建，不作为唯一证据；
  • 研究快照按复现和知识产权策略保留；
  • 个人信息执行最小化、用途限制和到期处理；
  • 退役数据产品保留所有者、替代项、最后支持日期和下游迁移状态；
  • 删除请求通过来源、湖仓、索引、缓存、备份和本体引用的可证明流程执行。
